# HTML 报告规范

## 信息结构

1. 项目名称＋单项目预审报告；
2. 已确认的申请背景；
3. 简短结论摘要；
4. 独立的“整体叙事是否 make sense”模块；
5. 设计思维、方案表达、视觉表达、页面文字四个项目维度；
6. 按原页序排列的逐页图文审核；
7. 按处理顺序排列、可回到对应页面的修改清单。

整体叙事模块必须位于四个项目维度和逐页点评之前，不能用首页一句总评、维度卡或零散逐页反馈代替。

## 逐页内容

每页包含：

- P1、P2 等明确页码；
- 完整原页面图，可点击放大；
- 处理顺序标签和一至两个相关内容标签，优先横向排列；
- 五个页面维度的简短状态与依据；
- 五轴雷达图；
- 本页成立之处、具体问题、位置与修改方向；
- 必要的跨页引用与跳转。

雷达图使用统一的 1—5 内部刻度，只表示当前页面呈现强弱。它不是项目总分、录取评分或页面排名，不显示加权总分。无法判断的项目应标注材料不足，不为了画满图形而猜测。

## 图片与 PDF

- PDF 每页直接渲染成完整图片，不截取阅读器窗口、工具栏或边框。
- 图片输入保留原文件顺序与文件名映射。
- 每条逐页解说必须紧邻对应完整页面图，不能用 OCR 文本代替。
- 图片保持比例，不裁掉页面内容；无投影、发光或悬浮阴影。
- 放大视图同样不添加阴影。
- 优先把图片内嵌进 HTML，或与 HTML 一起打包，确保本地打开时不丢图。

## 布局

- 宽屏使用一个完整连体面板：左侧页面图，右侧文字，右侧获得接近一半宽度。
- 左侧底色栏撑满整个面板高度；真正的页面图限制最大高度并在左栏内竖向居中。
- 左右两侧不能拆成两个独立卡片，也不能在左栏顶部或底部出现白色断层。
- 普通笔记本、平板和手机切换为上图下文；此时取消图片最大高度，让完整页面自然展示。
- 解释性正文统一为 14px。标题、标签、导航、图片说明和图表坐标可按功能使用不同字号。
- 不设置按问题等级筛选页面；页码导航使用 P1、P2 等可理解的标签。

## 视觉语言

不要固定使用紫色。结合封面和至少两张代表性内页识别稳定的项目主色，再转成一套低饱和强调色。项目没有稳定主色或无法可靠判断时，使用中性默认主题。

主体保持白色或接近中性的浅色，正文使用深色中性文字。主题色只用于标题、链接、标签、雷达图和少量状态提示，不能覆盖原作品或影响可读性。

删除没有信息作用的装饰元素，例如全大写英文眉题、纯装饰的 01／02 模块编号，以及已有页码时重复出现的 PAGE 01。

## 质量检查

交付前实际打开报告并检查：

- 所有页面图片、页码和文字对应正确；
- 整体叙事链路和跨页跳转有效；
- 放大查看、页码导航和修改清单链接可用；
- 宽屏左栏撑满且图片居中，窄屏无横向溢出；
- 正文统一为 14px，图片没有阴影；
- HTML 在本地离线打开时不缺资源。
